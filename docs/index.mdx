## A complete task

| Gate | Required outcome |
|---|---|
| Structure | All template files and metadata are complete |
| Environment | Cold build succeeds without privileged material |
| Oracle | Two independent runs receive `1.0` |
| NOP | Two independent runs receive `0.0` |
| Verifier | Valid alternatives pass; malformed, partial, and plausible-wrong outputs fail |
| Security | Agent cannot access solution, tests, ground truth, or credentials |
| Reproducibility | Clean repetitions produce stable verdicts |
| Submission | One task branch, one PR into `reviewed`; never directly into `main` |

The task format and quality rules follow the [official Terminal-Bench contribution guide](https://github.com/harbor-framework/terminal-bench/blob/main/CONTRIBUTING.md). Internal repository and approval rules are stricter where needed to protect the private dataset.

Use the left navigation in order. The manual explains prerequisites, initialization, every task file, exact validation commands, log diagnosis, completion criteria, private-repository branches, pull requests, and reviewer decisions.
